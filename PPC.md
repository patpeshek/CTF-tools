# PPC: какие задачи бывают и как их решает кит

PPC (Professional Programming and Coding / «программирование») — категория,
где вручную не успеть: сервис задаёт вопрос, ждёт ответ 2–8 секунд и так
N раундов, потом отдаёт флаг. Ошибка обычно закрывает соединение.

Этот файл — карта типов задач (по официальным сборникам и открытым репозиториям),
описание того, как движок сам понимает вопрос, и результаты локального стенда.

---

## 1. Как это выглядит

Два основных формата:

1. **Построчный диалог.** Сервис печатает вопрос, читает строку, проверяет.
   `nc host port`, вопрос → ответ → следующий.
2. **Полноэкранный терминал.** Сервис рисует одно окно ANSI-кодами и
   перерисовывает его на каждое действие (`\r`, очистка, курсор). Так делают
   почти все игры: Wordle, змейка, гонки, «поле».

Общие черты:

- жёсткий таймер на раунд (2–8 с), иногда общий (2 минуты на всё);
- 4–1000 раундов;
- на неверный ответ — `wrong`/`неверно` и разрыв, реже — просто следующий
  вопрос;
- handshake: иногда сначала надо отправить слово (`play-me`, `start`, ник);
- флаг в конце, иногда с задержкой/отдельным сообщением.

## 2. Таксономия задач

### 2.1 Числа и арифметика

| Тип | Как выглядит | Где встречалось | Чем берётся |
|---|---|---|---|
| Цепочка выражений | `12 + 7 * 3 - 5`, 100–1000 раундов, 5 с, «round to zero» | averov90/task-ppc (открытый), Иннополис «Calc» 2023/24 | `ppc_solvers.eval_expr` |
| Недостающий оператор | `12 ? 5 = 17`, 100 волн | NTUT-NPC/ppc-calculate (открытый) | `solve_missing_operator` |
| Предикаты чисел | «взаимно простые?», «простое?», YES/NO | пробник 2026/27, 2021/22 | `solve_coprime`, `solve_prime` |
| Теория чисел | НОД/НОК, делители, факториал, множители, Фибоначчи | общая практика | `solve_gcd`, `solve_divisors`, `solve_factorial`, `solve_fibonacci` |
| Последовательности | «продолжи: 2, 4, 6, 8» | общая практика | `solve_sequence` |
| Системы счисления | «переведи 255 в hex», двоичное | общая практика | `solve_base` |
| Степени/модули | `2^10 mod 1000` | общая практика | `solve_power_mod` |

### 2.2 Строки и текст

| Тип | Как выглядит | Где встречалось | Чем берётся |
|---|---|---|---|
| Гласные/согласные | «сколько гласных и согласных в “hello world”» | Иннополис «3:15» 2023/24 | `solve_string` |
| Реверс/сортировка/подсчёт | reverse, sort, count, replace | общая практика | `solve_string`, `solve_numbers_block` |
| l33t | `h3ll0` → `hello` | 2021/22 | правило + `enc` |
| OCR-капча | base64-PNG, «введи слово с картинки», 100–250 раз | 2021/22, 2023/24 | `solve_ocr` (pytesseract) |
| NLP-классификация | «определи эмоцию/тему», нужна точность 80–99% | Azarattum/TalkToMyChildren (открытый) | вне покрытия (нужна модель) |
| Wordle / «5 букв» | 5 букв, 3 с, 100 раундов, разметка буквами/эмодзи | ИнноКТФ (по описанию пользователя) | `wordle` / `game_bot` |
| Поиск слов | сетка букв + список слов | игры | `game_bot` + плагин |

### 2.3 Игры и интерактив

| Тип | Как выглядит | Чем берётся |
|---|---|---|
| Угадай число | «больше/меньше», 1..N | `game_bot` (бинарный поиск) |
| Гонка/аркада | «жми q», стамина/тонус, перерисовка | `game_bot --keys q --stamina N` |
| Wordle | см. выше | `wordle`, `game_bot` |
| Змейка/тетрис/матч-3 | поле, клавиши, перерисовка | `game_bot --record`, `--explore`, плагин |
| Турнирная сетка | имена/коэффициенты, выбрать победителей | плагин (правила задачи) |
| Викторина | команды Linux/Windows, 8 с на ответ | `oracle --auto` + знания |
| Лабиринт | 20×20, только вправо/вниз | `solve_grid_path` (BFS) |
| Игра N матчей | 200 партий, стратегия | плагин/математика |

### 2.4 Данные и алгоритмы

| Тип | Как выглядит | Чем берётся |
|---|---|---|
| Сборка картинки | куски PNG в архиве | `python` + Pillow (по сетке) |
| Формула Таппера | огромное число → картинка → OCR | `ppc_solvers` + OCR |
| RPN/постфиксная запись | инфикс → постфикс | `python` (стек) |
| Поток простых чисел | «отправь как можно больше простых» | генератор + `oracle` |
| CSV/JSON-агрегация | пагинация, лимиты, дедуп | `python`/`requests` |
| Графы/ДП | кратчайший путь, рюкзак, N ферзей | `python` (по условию) |
| Симуляции | Game of Life, физика, клеточные автоматы | `python` |

### 2.5 Специфика платформы

- вопрос может быть на **русском или английском** — ключевые слова в движке
  есть на обоих;
- ответ может требовать формат: `YES/NO`, число, слово, оператор, список;
- некоторые сервисы сначала просят handshake-слово;
- некоторые принимают только целую часть (`round to zero`);
- полноэкранные игры присылают не текст, а ANSI-перерисовку.

## 3. Как кит понимает задачу

```
чтение (TCP/локально)
   │  common.Screen: ANSI, \r, очистка, курсор → «экран»
   ▼
выделение вопроса: последние содержательные строки
   ▼
классификация: ключевые слова RU/EN → тип; если не вышло — по форме данных
   ▼
ppc_solvers.candidates(): список (стратегия, ответ), от вероятного к редкому
   ▼
отправка ответа → наблюдение (новый раунд / wrong / обрыв)
   ▼
серия успехов N → стратегия закрепляется за классом
обрыв/«wrong» → следующая гипотеза, переподключение
   ▼
флаг: common.FlagGrabber (куски, ANSI, zero-width, base64) — всегда
```

Команды:

```powershell
python toolbox.py oracle --connect host:port --auto     # Q&A-сервисы
python toolbox.py game   --connect host:port --auto     # экран/игры/клавиши
python toolbox.py game   --connect host:port --record game.log
python toolbox.py oracle --connect host:port --auto --promote 10 --dump q.txt
```

Если вопрос незнаком:

```powershell
python toolbox.py game --connect host:port --auto --explore   # какие клавиши реагируют
```и плагин `plugins/имя.py` (`PLUGIN = {..., "move": ...}`), шаблон —
`plugins/_template.py`.

---

### Если задач несколько

На каждый сервис — свой процесс, инструмент один и тот же:

- чистый Q&A → `oracle --auto`;
- экран/игры/клавиши → `game --auto`;
- не уверен → `game --auto` (сам сведётся к Q&A).

Параллельно — нормально: разные окна/порты, каждому можно включить `--dump`
или `--record`. Отдельный скрипт под каждый тип не нужен; для незнакомого
протокола один раз пишется плагин, дальше он подхватывается по баннеру.

## 5. Чего не хватает (честно)

- **NLP/ML-классификация** (TalkToMyChildren): без модели/словаря не решить;
  нужен плагин с `compromise`/своим классификатором.
- **Незнакомые игры** (змейка, тетрис, матч-3): движок покажет экран и
  рабочие клавиши (`--explore`), но стратегию надо описать плагином.
- **Сложные изображения** (искажённые капчи, ребусы): OCR работает на чистых;
  для сложных — предобработка/ручной ввод.
- **Огромные данные** (гигабайты CSV, streaming): нужен отдельный скрипт.
- **Шахматы/движки, NP-задачи с большим N**: по условию, не универсально.
- **Кастомные протоколы** (бинарные, WebSocket): `--record` + плагин.

Универсальность здесь — не «магия», а широкий набор гипотез + честный отказ:
если движок не понял, он сохраняет протокол и говорит, чего не хватило.

## 6. Как добавить свой тип

1. Открыть `pwn/ppc_solvers.py`.
2. Написать функцию `solve_x(q) -> str | None` (q["text"] — вопрос).
3. Добавить в `SOLVERS` строку `("x", _kw(r"ключевые|слова"), solve_x)`.
4. Добавить кейс в `tests/ppc_bench.py` (генератор + ответ).
5. `python tests/ppc_bench.py --only x`.

Для интерактивных игр — плагин:

```python
def move(text, state):
    if "нажми q" in text.lower():
        return "q"
    return None

PLUGIN = {"name": "my-game", "kind": "interactive",
          "match": {"banner": r"Моя игра"}, "move": move}
```
