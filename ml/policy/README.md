# `ml/policy` — политика действий (эксперимент, за кулисами)

Это отдельный слой поверх роутера. Роутер отвечает «**что за файл**», политика —
«**какой инструмент сработает**». Обучена не на синтетике, а на настоящих
трассах: как солвер реально решал 2213 задач из архива CTF.

**По умолчанию не включена.** Влияния на результаты замера не показала (см.
ниже), поэтому в `solve.py` включается только явно:

```
python solve.py <задача> --smart --policy ml/policy/policy_best.npz
```

## Что лежит здесь

| файл | что это |
|---|---|
| `policy_best.npz` | сама модель, чистый numpy, 62 КБ: 3 линейных слоя + GELU, вход — признаки файла + one-hot инструмента + позиция шага |
| `traces_big.jsonl.gz` | полный набор трасс (2213 задач, ~2 МБ в сжатом виде): по строке на задачу, внутри список шагов |
| `sample_traces.jsonl` | те же 20 первых строк без сжатия — чтобы посмотреть формат глазами |

Полные артефакты обучения (чекпоинт torch, датасет `policy_big3.npz`, логи)
лежат вне репозитория: `F:\AIproject\ml-runs\`.

## Цифры (честные)

| метрика | значение |
|---|---|
| задач в трассах | 2213 |
| из них с правдоподобным флагом | 576 (26%) |
| пар «состояние + инструмент» | ~30 тыс. |
| AUC на отложенных задачах | **0.843** |
| top-1 / top-3 / MRR | **0.68 / 0.82 / 0.76** |

## Почему выключена

1. **Солвер запускает шаги пачками параллельно**, поэтому порядок внутри
   пачки почти не влияет на то, дойдёт ли он до флага. Замер: 121 шаг против
   121 на шести задачах — разницы нет.
2. На задаче про LSB политика опустила правильный инструмент с первого места
   на третье (она училась на архиве, где LSB редок).

Чтобы политика начала приносить пользу, нужен другой механизм исполнения:
**последовательный запуск с ранним выходом** (топ-1 → проверили → следующий,
или пачками по 2). Тогда порядок станет решающим, а top-1 0.68 начнёт
превращаться в секунды.

## Как это воспроизвести

```
# 1. трассы (долго: ~час на 2000 задач)
python ml\collect.py --roots F:\AIproject\ctf-files\archive --time 12 ^
    --out F:\AIproject\ml-runs\traces.jsonl

# 2. датасет «состояние + инструмент → успех»
python ml\build_policy_data.py --traces <traces.jsonl> ^
    --out F:\AIproject\ml-runs\policy.npz

# 3. обучение (метрики AUC и ранжирование)
python ml\train_policy.py --data F:\AIproject\ml-runs\policy.npz ^
    --epochs 40 --out F:\AIproject\ml-runs\policy.pt

# 4. перенос в numpy (кит живёт без torch)
python ml\export_policy.py --model F:\AIproject\ml-runs\policy.pt ^
    --out ml\policy\policy_best.npz
```

## Осторожно с метриками

Первая версия показывала top-1 0.96 — и это была **утечка**: в признаках шага
передавались `status` («шаг завершился ok») и число найденных флагов, то есть
модель «предсказывала» уже случившееся. Признаки исправлены: теперь только то,
что известно **до** запуска шага. Если будешь добавлять свои — не тащи туда
последствия.
