# Сайт — тонкий прототип

Сквозной минимум: страница → загрузка файла → запуск `solve --events -` →
живой лог шагов и флаг в браузере. Тикеты #143 (API), #146 (форма), #147 (поток).

## Запуск

```bash
python site/app.py            # http://127.0.0.1:8770
```

Только стандартная библиотека. Но движок (`solve`) требует зависимости проекта
(`pip install -r requirements.txt`) и внешние утилиты для части инструментов
(Ghidra/hashcat/tesseract) — что стоит, то и работает.

Переменные: `PORT` (8770), `BIND` (127.0.0.1).

## Два режима запуска движка

- **Есть Docker** → изолированная песочница (`site/sandbox/runner.py`, #142).
- **Нет Docker** → прямой ЛОКАЛЬНЫЙ запуск без изоляции. Годится проверить
  «решает/нет» на своей машине; для чужих файлов нужна песочница. Страница
  показывает жёлтое предупреждение в этом режиме.

## Что это НЕ

Прототип, не продукт. Нет: логина (#149), очереди (#144), истории (#145/#154),
страницы результата и скачивания артефактов (#148), веб-режима с сетью и защиты
самого сайта (#152). Биндится на `127.0.0.1` — наружу не выставлять.

## Поток событий

Браузер слушает `GET /events/<job_id>` (SSE). Формат — ровно контракт движка
(`docs/SITE.md` §4): `plan` / `step_start` / `step_end` / `lead` / `flag` /
`done`, плюс `runner_note` от самого сервиса.
