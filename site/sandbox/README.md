# Песочница запуска движка `solve` (#142)

Запуск движка `solve` на **недоверенном** задании внутри одноразового
контейнера. Первый кусок песочницы из `docs/SITE.md` (#141/#142): сборка команды
запуска, профиль изоляции, стрим JSON-событий движка наружу генератором и
безопасный dry-run, когда docker недоступен.

Полный дизайн и модель угроз — `docs/SITE.md` (PR #165). Коротко: загружаемый
файл считаем враждебным, движок к этому не готов (RCE при разборе, бомбы
архивов, выход за папку, эксфильтрация), поэтому движок **нельзя** запускать на
хосте — только в контейнере без сети, без прав и с жёсткими лимитами.

## Файлы

| Файл | Что это |
|---|---|
| `runner.py` | сборка команды, запуск контейнера, стрим и парсинг событий |
| `Dockerfile` | минимальный образ движка (slim-Python + `requirements.txt`) |
| `test_runner.py` | тесты без docker: сборка команды и парсинг потока |

## Быстрый старт

Собрать образ (контекст сборки — **корень репозитория**, т.к. код движка лежит
в корне):

```bash
docker build -f site/sandbox/Dockerfile -t ctf-sandbox:latest .
```

Запустить задание и получить поток событий (по строке на событие):

```bash
python site/sandbox/runner.py path/to/challenge.bin
```

Только собрать и посмотреть команду, ничего не запуская:

```bash
python site/sandbox/runner.py path/to/challenge.bin --print-command
```

Из кода (бэкенд-оркестратор так и будет это дёргать):

```python
from site.sandbox import runner  # или: import runner, если внутри site/sandbox

for ev in runner.run("challenge.bin", timeout=120, flag_format="picoCTF"):
    # ev — dict одного события движка: plan / step_start / step_end / lead /
    # flag / done; в конце служебное runner_end. Пересылать как есть (SSE).
    print(ev["event"])
```

## Профиль изоляции

Один эфемерный контейнер на задание (`docker run --rm`). Команду собирает
`runner.build_command`; профиль (тикет #142 + `SITE.md` §5):

| Флаг | Зачем |
|---|---|
| `--network none` | сети нет (offline-режим по умолчанию) |
| `--read-only` | корневая ФС только на чтение |
| `--tmpfs /work:rw,size=512m,nosuid,nodev,noexec` | единственное место записи — скретч в памяти |
| `-v <вход>:/in/<имя>:ro` | вход смонтирован только на чтение |
| `-w /work`, `-e TMPDIR=/work`, `-e HOME=/work` | все записи уводятся в tmpfs |
| `--memory 1g --memory-swap 1g` | лимит памяти, swap выключен (OOM-kill вместо качелей) |
| `--cpus 2` | лимит CPU |
| `--pids-limit 256` | против форк-бомб |
| `--ulimit nofile=1024` | лимит дескрипторов (`--ulimit fsize=…` опц., против бомб на диск) |
| `-u 10000:10000` | запуск не-root |
| `--cap-drop ALL` | сняты все capabilities |
| `--security-opt no-new-privileges` | нельзя поднять привилегии |
| без проброса `docker.sock`, без host-mount кроме скретча | нет выхода на хост |

Seccomp — профиль docker по умолчанию (отдельный флаг не нужен). Усиление, если
доступно (`SITE.md` §5): рантайм gVisor (`runsc`) вторым слоем, на ноутбуке —
rootless Podman. Тяжёлые/опасные инструменты (Ghidra, hashcat) в базовый образ
**не** входят — по дизайну подключаются отдельной опцией (`SITE.md` §5, вопрос №3).

### Настенный таймаут

Жёсткий таймаут держит **runner**, а не движок: через `timeout` секунд
(по умолчанию 120) контейнер снимается `docker kill` независимо от того, что
внутри. Бюджет движка `--time` (по умолчанию 90) этому не замена — это мягкая
самоостановка движка раньше жёсткого kill. Переопределить бюджет движка —
`--engine-budget` / `engine_budget=`.

## Контракт движка (stdout)

`runner` сам challenge-файл не разбирает — только пробрасывает строки stdout
контейнера. Каждая строка — одно событие (`SITE.md` §4):

```json
{"event": "plan|step_start|step_end|lead|flag|done", "t": 0.0, "...": "поля"}
```

`run()` отдаёт эти события как dict'ы генератором, плюс в конце своё служебное
`runner_end` (`returncode`, `timed_out`). При недоступном docker — одно
`runner_note` (dry-run, см. ниже). События самого runner — из набора
`runner.RUNNER_EVENTS`, их легко отличить от событий движка.

### `--events -` против `--json -`

Дизайн-документ называет машинный поток `solve --json -`. В самом движке это
**два** разных флага, и для построчного потока событий нужен `--events -`:

* `--events -` — поток событий §4 (plan/step_start/step_end/lead/flag/done) в
  stdout, человеческий лог → stderr. Это то, что стримит песочница.
* `--json` — одна финальная сводка-объект (status/flag/steps/…) в конце.

Поэтому runner по умолчанию зовёт `solve.py <target> --events -`. Финальную
сводку можно добавить опцией `--summary` / `want_summary=True` (допишет `--json`).

## Режимы: offline / web

* **offline** (по умолчанию) — `--network none`, сети нет вообще. Основной
  режим турнира; крипто/стего/форензика/реверс/PPC работают полностью.
* **web** — для recon/param по URL нужен выход наружу. Контейнеру нужна сеть с
  **egress-allowlist только на хост цели**, которую поднимает оркестратор
  (iptables/прокси — `SITE.md` §7). Сам контейнер так себя ограничить не может,
  поэтому `build_command(mode="web")` **требует** явного `network=<имя сети>` и
  иначе кидает `ValueError`. Фильтрацию egress в этом куске мы не реализуем —
  это уровень оркестратора (#143/#152); здесь — только безопасный по умолчанию
  интерфейс, который не даст случайно открыть полную сеть.

```bash
# оркестратор заранее поднял сеть ctf-egress с allowlist на хост цели:
python site/sandbox/runner.py target.txt --mode web --network ctf-egress
```

## Dry-run без docker

Если docker не установлен или демон не отвечает, runner **не падает**: `run()`
отдаёт одно событие `runner_note` с собранной командой (списком и строкой) и
понятным сообщением, ничего не запуская. Так песочницу можно собирать и
тестировать на машине без docker, а бэкенд — заранее показать команду.

```bash
# docker отсутствует -> в stdout одно событие runner_note с полями
# command / command_str / message, контейнер не стартует
python site/sandbox/runner.py challenge.bin
```

## Тесты

Без docker — проверяют сборку команды (весь профиль изоляции, маппинг входа на
`:ro`, режимы, таймаут-опции) и построчный парсинг потока событий, включая
dry-run:

```bash
python site/sandbox/test_runner.py
```

Ожидаемо: `OK` (14 тестов). Docker для тестов не нужен.

## Замечания по эксплуатации

* **Контекст сборки** — корень репозитория (`-f site/sandbox/Dockerfile`).
  Корневой `.dockerignore` (чтобы не тащить `.git`/тесты в образ) стоит завести
  отдельно — вне этого тикета.
* **Windows.** Профиль рассчитан на Linux-хост (сервер / ноутбук с Kali,
  `SITE.md` §8). На Docker Desktop под Windows bind-mount пути транслируются
  средой; прод-развёртывание — Linux.
* **Офлайн-финалы.** Образ движка и базовый образ песочницы собираются и
  сохраняются заранее (`docker save`/`load`), в рантайме из сети ничего не
  тянется (`SITE.md` §8).
* **Границы доверия.** Оркестратор валидирует только метаданные (размер,
  заявленный тип) и кладёт файл в скретч задания; весь разбор — внутри
  контейнера. Вывод движка — не доверенный текст, экранировать при показе
  (`SITE.md` §7, #152).
